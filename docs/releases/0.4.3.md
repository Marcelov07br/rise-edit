# 0.4.3 — direct timeline interaction

The selected main video clip now exposes both trim edges. Dragging an edge previews a draft
in the timeline and commits one persisted edit on release. Undo/redo remains one step per
gesture. Previously trimmed source footage can be restored within the original media limits;
speed points and clip effects are preserved.

Pinch zoom works over clips, the ruler and empty track rows. Horizontal dragging pans the
viewport; vertical dragging scrolls tracks; holding and dragging a clip moves it. The viewport
uses a fixed width and draws visible time ranges instead of allocating an enormous timeline.

The calculation layer is pure JVM (`core.editing`). UI gesture arbitration, viewport state,
layout, thumbnails, waveform, ruler and action routing live in separate `timeline` components.
Gesture commits target clip IDs and verify the original snapshot before applying an edit.
Project JSON schema 3, application ID and distribution signature are preserved.

This first interaction slice trims main video clips only. Direct edge handles for audio,
overlays and text, and transitions attached to joins, remain subsequent work.

Validation: 57 JVM tests passed locally. Native tests exercise real two-finger zoom on clips
and empty tracks, both trim edges, restoration, cancellation, single-step history, reopen,
preview source timing, export duration/frame availability and unchanged source bytes.
Native validation and signed APK delivery are pending until those checks pass.
