# 0.4.4 — faster, steadier stabilization analysis

Motion analysis now decodes the video sequentially with MediaCodec instead of one
MediaMetadataRetriever seek per sample. Only the luma plane is read (10-bit/HDR via the
high byte), downscaled to at most 640 px and rotated to display orientation, at up to ~33
samples/s. Devices whose decoder output cannot be read fall back to the previous path.

- Smoothing is O(n) (two-pass sliding window, triangular kernel); smooth and fixed-camera
  modes and strength are unchanged.
- Crop zoom now varies over time: a local maximum of the required zoom, eased in and out,
  never above the chosen limit and never below what hides the borders. One shaky moment
  no longer crops the whole clip.
- Tracking losses up to 1 s are bridged by interpolating the motion instead of resetting the
  camera pose; longer losses still start a new segment.
- Analyses are cached per source (uri + size + modification time); re-analyzing the same
  file is instant.
- Source limit raised from 2 to 20 minutes (2 minutes on the fallback path).
- UI-agnostic API: `MotionAnalyzer.analysisFlow(clip)` emits progress and the result.

Validation: `./build-local.sh check` (detekt, ktlint, JVM tests, lint) passed locally. JVM
smoothing benchmark: 2 min source 89 ms → 3.5 ms, 10 min 542 ms → 11 ms, 30 min 51 ms.
